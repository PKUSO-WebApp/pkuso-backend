# 谱务识别的过拟合审计（2026-10-17）

**性质：只诊断，不改行为。** 本文列出的每一条都是「这里存在一个假设」，不是「这里该这么改」——
修法要另立项、另拍板。文档之外本次**没有动任何一行业务代码**。

**为什么在 `docs/` 而不是 `audit/`**：`audit/README.md` 自己写明那是「MCP 操作审计日志（历史目录）」，
有固定的记录模板（时间/操作者/环境/操作类型），且「正常情况下这里不会再有新文件」。
本文不是 MCP 操作记录，放进去会让那份 README 变成假话。

**行号口径**：所有 `file:line` 都是 2026-10-17 的 `origin/main` 行号；每一条都附了可搜的原文片段，
行号漂了就用片段重新定位。

**审计范围**：`segment-parts/`、`llm-analyze/`、`ocr-analyze/` 与 `_shared/` 里这条链路用到的共用件。
**判据只有四问**：① 它编码了什么假设；② 那个假设是普遍的，还是只为某几份语料成立的；
③ 什么观测会证伪它；④ 更普适的写法是什么。

**归类**：`普遍（有依据）` / `特化（为语料调的）` / `存疑（证据不足，缺什么写在条目里）`。

## 0. 一页纸结论

### 0.1 最重要的一条：prompt 规则不是这条链路的杠杆

三条互相独立的实测指向同一结论：

1. **改措辞零改善**。#96 §3.1 把规则 1 改成「第 1 页是首页范例」，走完整验收矩阵后
   该切命中率 **29/63 → 29/63**（与记录基线同值），回归红线未动。已回退（`e67f0c6`），
   并在 issue 里明确「别再重新提出换一种措辞试试，除非先给出可证伪预期」。
2. **同构输入给出相反答案**。2026-10-16 矩阵：舒八 `长笛1+长笛2` 9/9 切、`双簧管1+双簧管2` 9/9 弃权；
   本次审计当场复算 `pagetexts.json`（`.render-harness/seg-replay/out/pagetexts.json`），
   两份的 p1/p5 窄带逐字同构（只差乐器名）：

   ```
   长笛 p1: Flauto I / Sinfonie in h-moll • B minor / „Unvollendete" • "Unfinished"
   双簧管 p1: Oboe I  / Sinfonie in h-moll • B minor / „Unvollendete" • "Unfinished"
   ```
   也就是说：**判据在进模型之前已经给足了，差异出在模型侧**。再加一条 prompt 规则，
   既不能解释 0/9 与 9/9 的差，也不能稳定它。
3. **弃权是模型直接弃权**。漏切的三份共 27 轮全部 `rawCuts=[]`（`rejected` 324 轮一次没非空过）
   ⇒ 不是被 evidence 校验丢掉的，改校验侧没有可修的对象。

⇒ **方针的直接推论**：这条链路接下来的改进不在「再补一条规则」，而在
**把不确定性显式交给人**、**输入侧质量**、**成本**（#96 2026-10-17 评论已按此重排批次）。
每新增一条 prompt 规则，都是往一个已经证明「改它没收益」的表面再加一个未验证的变量。

## 3. 看着像特例、其实是普遍判据（**别动**）

这一节是纪律的另一半：把下面这些当成上面的同类去「清理」，会把有依据的设计拆掉。

1. **`SECTIONS` 十六声部闭集**（`analyze.ts:16-33`）——**不是**「照本乐团花名册抄的」。
   证据：① 与 pkuso-web 的 `INSTRUMENT_ORDER` 有显式逐字对账要求；② 它是落库分组键；
   ③ 闭集外的值有**设计好的出口**（「其他」+ `sectionRaw` + 用户手填，`normalizeSection` 不做猜测性归并）。
   「未知新乐器怎么办」的答案是**显式暴露 + 人工落点**，不是「词表永远够用」。
2. **`providedSubParts` 只认结构性的「没有」**（`analyze.ts:457-463`）——注释明写「**不再用词表**认『无』…那是一条开放的用词清单，加不全，每加一个都可能误伤」。
   这是本文提倡的写法在**代码里**的现成样例，不是历史包袱。
3. **规则 4「版次语言由出版社决定，不由作曲家国籍决定」**（`handler.ts:226-229`）——一条**去偏规则**：
   它防的是拿作曲家的国籍去推版次语言。例子是样本，规则本身是对「别用一个代理变量替另一个」的普遍要求。
4. **规则 0 的总谱判据**（`handler.ts:190-211`）——给的是**版式定义**（同一页并列多个乐器），
   不是词表；且预先点掉最可能的两种误判（「出现了乐器名」、「一件乐器加调性算两件」），并明说与语言无关。
5. **`evidence` / `evidenceFound` 用 `typeof` 判型而不是 `??`**（`analyze.ts:611-621`）——「没这个字段」与
   「模型给了空串」在界面上**不等价**，那是产品语义（记忆里特别记过这一条是「看着像兼容层其实不是」）。
6. **`sectionRaw` / `subPartsRaw` / `evidenceFromFileName`**——都是「把静默差异变成可见信号」的字段，
   不是旧版本的兼容残留。删它们的理由是「没人读」（web#302 那半），不是「过拟合」。
7. **`MAX_*` 上界与 `MIN_EVIDENCE_CHARS`、`BLANK_LETTERS`、`UNSAFE_IN_NAME`、`VISIBLE`**——
   全部是**形状/防御**类判据：防的是「荒唐输出」「空串是任意串的子串」「看不见的字符冒充内容」
   「名字落不了盘」。它们不依赖任何语料。数字是拍的，但方向是「触顶说明模型在胡说」，不是「这份谱刚好对」。
8. **`defuseFence`、重试/超时策略、CORS 三份常量**——上游与协议的形状问题，与语料无关；
   其中 CORS 三份**刻意不统一**（合并两个方向都是行为变更）。
9. **`ocr-analyze` 里处处「宁可退化成没有坐标，也不产生看起来合法的错值」**（`coord` 拒绝 `null`/`""`；
   宽高缺省 0；`FileParseExitCode` 缺失不判失败）——与本文方针同向，是「不确定性不伪装成结论」的样例。

## 5. 需要你拍板的两件事

1. **D4（规则 6 的易混词表）删还是留。** 它与 #27 删掉五张词表的理由同源（维度发散），

   本文不给结论，只给证据（其中 `Campanelli/Silofono` 一条的依据已随 #27 消失）。
2. **两条链路在「不确定」上的方向要不要统一。** `llm-analyze` 的既定原则是
   「弃权是最后手段」（找不到引文照样采用答案，只把事实回传）；`segment-parts` 的既定原则是
   「宁可少切」（不确定一律不切）。两者都有理由（代价不对称），但**同一个系统里
   对『不确定』给了相反的处置**，而这正是「泛化的兜底」该落在哪里的问题。
   方针写的是「不确定就不做决定（弃权优于猜）」—— 与 `segment-parts` 一致，
   与 `llm-analyze` 的现状相反（那边是「采用 + 标记，让人覆盖」）。
   两种都算「不看数据就下结论」，但**回传给人**的那一种更接近「把不确定性显式暴露给人」。
